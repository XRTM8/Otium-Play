# ZOET by Otium 2.0

تطبيق Android وويب مكتوب بمنطق Rust، بواجهة WebAssembly ومحرك مصادر مشترك يعمل مباشرة من شبكة المستخدم.

- شبكة للمسلسلات وشبكة مستقلة للأفلام. لا صفوف أفقية ولا واجهات تسويق.
- تصفّح جميع صفحات المصدر، بحث متعدد الصفحات، ودمج الأعمال المطابقة مع الحفاظ على كل مصدر.
- تفاصيل المسلسل وحلقاته بقائمة عمودية، مع المواسم والبحث داخل الحلقات.
- تجهيز المصدر البديل قبل إيقاف الحالي، وحفظ الموضع والإيقاف والسرعة والصوت. فشل التحويل يعيد المصدر السابق.
- HLS متكيّف، تحكم بالجودة، ترجمة سينمانا، سجل ومفضلة وإيماءات واختصارات لوحة المفاتيح والريموت.
- زجاج داكن معتم، احترام تقليل الحركة، وتنسيق للهاتف والكمبيوتر وAndroid TV.

الأفلام متاحة من سينمانا حالياً. قرمزي مخصص للمسلسلات في هذا الدمج. توفر سينمانا مرتبط بمزوّد الإنترنت؛ التطبيق لا يتجاوز قيود الشبكة.

## تشغيل الويب

```sh
cargo run --manifest-path rust/otium-core/Cargo.toml --locked --release
```

افتح `http://localhost:3000`. لا يحتاج التشغيل إلى Node.js. ملفات WebAssembly المبنية موجودة في `public/wasm`؛ لتعديل منطق الواجهة أعد بناءها بواسطة `scripts/build-rust-ui.ps1` بعد تثبيت Rust وهدف `wasm32-unknown-unknown` و`wasm-bindgen-cli 0.2.130`.

## بناء Android

```powershell
./scripts/build-rust-ui.ps1
./scripts/build-rust-android.ps1
gradle -p android assembleRelease
```

تحتاج Android SDK/NDK وJava17 وأهداف Rust الأربعة الموثقة في [بنية Rust](RUST_MIGRATION.md). راجع [التوقيع الثابت](SIGNING.md). لا ترفع ملفات المفاتيح إلى GitHub. بقي `applicationId=com.krmzi.app` ومفاتيح السجل القديمة حفاظاً على هوية الحزمة والبيانات.

## التحقق

```sh
cargo test --manifest-path rust/otium-core/Cargo.toml --locked
cargo test --manifest-path rust/otium-ui/Cargo.toml --locked
node tests/rust-ui.test.cjs
```

اختبارات الواجهة تشغّل WebAssembly الحقيقي مع مصادر وأحداث فيديو محاكية. تحتاج Playwright ومتصفح Chromium؛ متغيرا `PLAYWRIGHT_MODULE` و`BROWSER_PATH` يحددان مساراتهما. فحص المصادر والفيديو الحي اختياري عبر `node tests/live-rust-smoke.cjs` بعد بناء المحرك بوضع debug.

`Space/K` تشغيل وإيقاف، `J/L` عشر ثوانٍ، الأسهم الأفقية خمس ثوانٍ أو30 مع `Shift`، الأسهم العمودية للصوت، `M` كتم، `F` ملء الشاشة، `P` صورة مصغرة، `C` ترجمة، `E` حلقات، `S` مصادر، `Q` جودة، `N` التالية، `[` و`]` للسرعة. `?` يعرض الدليل.

## حدود معروفة

- منطق التطبيق والواجهة والمشغل والمصادر مكتوب بـRust. HTML/CSS للتنسيق، وJavaScript المولد يربط WebAssembly بالمتصفح، وHLS.js مكتبة خارجية. Kotlin طبقة Android للنوافذ وJNI ودورة الحياة فقط.
- لا يمكن مزامنة وقت مشغّل iframe خارجي عبر أصل مختلف؛ التحويل المباشر بين قرمزي وسينمانا يحفظ الوقت والإعدادات. قد تختلف مقدمة الحلقة أو مدتها بين المصدرين.
- المطابقة الآلية تتطلب هوية العمل ورقم الحلقة والموسم. الأعمال المعاد إنتاجها والنتائج الملتبسة لا تُدمج عشوائياً.
- واجهة الشاشات الذكية لا تعني وجود حزم أصلية مستقلة لـTizen/webOS.
- يطلب Android معدل تحديث حتى120Hz ضمن دقة الشاشة الحالية. ثبات120FPS يحتاج قياساً على جهاز فعلي يدعمه؛ معدل الفيديو الأصلي مستقل عن معدل الواجهة.
